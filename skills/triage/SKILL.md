# Triage

Move tasks in `cmd` through a small state machine of triage roles.

> 📝 **Triage primarily UPDATES existing tasks** (labels, comments, status). It does not normally create new root tasks — that's the job of `/to-prd` or `/to-issues`. If during triage you find that something needs to be filed as a new task, route to `/to-prd` (for a PRD-shaped root) or `/to-issues` (for vertical slices), both of which require `--mission-brief` for root creation per the `CLAUDE.md` pre-flight checklist.

Every comment or task posted to `cmd` during triage **must** start with this disclaimer:

```
> *This was generated by AI during triage.*
```

## Reference docs

- [AGENT-BRIEF.md](AGENT-BRIEF.md) — how to write durable agent briefs

## Roles

Two **category** roles (cmd labels):

- `bug` — something is broken
- `enhancement` — new feature or improvement

Five **state** roles (cmd labels, prefixed `triage:`):

- `triage:needs-triage` — maintainer needs to evaluate
- `triage:needs-info` — waiting on reporter for more information
- `triage:ready-for-agent` — fully specified, ready for an AFK agent
- `triage:ready-for-human` — needs human implementation
- `triage:wontfix` — will not be actioned

Every triaged task should carry exactly one category label and one state label. If state labels conflict, flag it and ask the maintainer before doing anything else. For `triage:wontfix`, also set `cmd task update <id> --status cancelled`.

State transitions: a newly-created task normally goes to `triage:needs-triage` first; from there it moves to `triage:needs-info`, `triage:ready-for-agent`, `triage:ready-for-human`, or `triage:wontfix`. `triage:needs-info` returns to `triage:needs-triage` once the reporter replies. The maintainer can override at any time — flag transitions that look unusual and ask before proceeding.

## cmd commands (canonical)

```bash
# Identify yourself on every write
RUNTIME="--runtime claude-code --model claude-opus-4-7"

# List tasks needing attention
cmd task list --labels triage:needs-triage
cmd task list --labels triage:needs-info

# Show a task and its context (comments, labels, dependencies)
cmd context <id>

# Apply category + state labels
cmd task update <id> --labels bug,triage:needs-triage $RUNTIME

# Post triage notes (comment must begin with the AI disclaimer)
cmd task comment <id> "> *This was generated by AI during triage.*

..." --type progress $RUNTIME

# Close out a wontfix
cmd task update <id> --labels enhancement,triage:wontfix --status cancelled $RUNTIME
```

## Invocation

The maintainer invokes `/triage` and describes what they want in natural language. Interpret the request and act. Examples:

- "Show me anything that needs my attention"
- "Let's look at agent-pi-eb3m"
- "Move agent-pi-eb3m to ready-for-agent"
- "What's ready for agents to pick up?"

## Show what needs attention

Query `cmd` and present three buckets, oldest first:

1. **Unlabeled** — never triaged. (`cmd task list` and filter for tasks without any `triage:*` label)
2. **`triage:needs-triage`** — evaluation in progress. (`cmd task list --labels triage:needs-triage`)
3. **`triage:needs-info` with new comments since the last triage notes** — needs re-evaluation. (`cmd task list --labels triage:needs-info` then `cmd context <id>` to inspect comment timestamps)

Show counts and a one-line summary per task. Let the maintainer pick.

## Triage a specific task

1. **Gather context.** Run `cmd context <id>` to read the full task (description, comments, labels, dependencies, timestamps). Parse any prior triage notes so you don't re-ask resolved questions. Explore the codebase using the project's domain glossary, respecting ADRs in the area. Read `.out-of-scope/*.md` and surface any prior rejection that resembles this task.

2. **Recommend.** Tell the maintainer your category and state recommendation with reasoning, plus a brief codebase summary relevant to the task. Wait for direction.

3. **Reproduce (bugs only).** Before any grilling, attempt reproduction: read the reporter's steps, trace the relevant code, run tests or commands. Report what happened — successful repro with code path, failed repro, or insufficient detail (a strong `triage:needs-info` signal). A confirmed repro makes a much stronger agent brief.

4. **Grill (if needed).** If the task needs fleshing out, run a `/grill-with-docs` session.

5. **Apply the outcome** (via `cmd task update <id> --labels <cat>,triage:<state>` + `cmd task comment` for narrative):
   - `triage:ready-for-agent` — post an agent brief comment ([AGENT-BRIEF.md](AGENT-BRIEF.md)) via `cmd task comment`.
   - `triage:ready-for-human` — same structure as an agent brief, but note why it can't be delegated (judgment calls, external access, design decisions, manual testing).
   - `triage:needs-info` — post triage notes via `cmd task comment` (template below).
   - `triage:wontfix` (bug) — polite explanation via `cmd task comment`, then `cmd task update <id> --status cancelled`.
   - `triage:wontfix` (enhancement) — write to `.out-of-scope/`, link to it from a `cmd task comment`, then `cmd task update <id> --status cancelled` ([OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)).
   - `triage:needs-triage` — apply the label only. Optional `cmd task comment` if there's partial progress.

## Quick state override

If the maintainer says "move agent-pi-eb3m to ready-for-agent", trust them and apply the label directly. Confirm what you're about to do (label changes, comment, status), then act. Skip grilling. If moving to `triage:ready-for-agent` without a grilling session, ask whether they want to write an agent brief.

## Needs-info template

```markdown
> *This was generated by AI during triage.*

## Triage Notes

**What we've established so far:**

- point 1
- point 2

**What we still need from you (@reporter):**

- question 1
- question 2
```

Capture everything resolved during grilling under "established so far" so the work isn't lost. Questions must be specific and actionable, not "please provide more info".

## Resuming a previous session

If prior triage notes exist on the task (visible via `cmd context <id>`), read them, check whether the reporter has answered any outstanding questions, and present an updated picture before continuing. Don't re-ask resolved questions.
